# Registry review before delivery

Reviewed `9ccd1a0...HEAD` against issue #356 and CLAUDE.md. Parallel review workers could not
start because the configured worker delivery was rejected; both axes below were reviewed here.

## Standards

One hard finding: credential material could be read for a different installation snapshot.
`installed::values` read a secret id by account/plugin name, then fetched its ciphertext in a
second statement. A turn with a bundle captured before uninstall/reinstall could therefore bind
a replacement credential to its old endpoint definitions. That conflicts with the credential
boundary in CLAUDE.md and with the install comment promising that update does not reuse tokens
across changed remote URLs.

Fixed by reading snapshot eligibility and ciphertext in one Postgres statement. The runtime
passes its captured installation to that reader; vault opening uses only the ciphertext already
read, not a second name lookup. The snapshot's install timestamp and serialized bundle must match.
Installation incarnation/version handling in #359/#364 strengthens this boundary further.

No additional non-tooling standards violations found in this bounded review. Crate edges and
ceilings remain enforced. Provider rules/tests and SQL extraction preserve their original content.

## Spec

Issue #356 requires installs to remain pinned and account-owned until an explicit update. The
credential rebinding above weakened that pin at the moment a running turn read credentials.
A regression test reproduces the mismatch after uninstall/reinstall and verifies that an old
snapshot receives no replacement token while the current snapshot receives its own token.
The test was observed failing before the fix and passing afterwards.

The catalog, install/uninstall, connector listing, shared-Bot account isolation, and unsupported
part reporting are implemented. OAuth, multiple accounts and the chooser remain separate,
explicitly tracked features; neither anonymous Exa transport proof nor an OAuth refusal closes them.

Summary: Standards 1 finding fixed; Spec 1 finding fixed. Remaining items are the approved
follow-up features, not hidden completion claims.
