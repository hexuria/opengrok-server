The One Card

A coworker wants to do something you might not want done. There is exactly one place you are asked, one card, four answers — and it never expires. Here is why each of those words was chosen.

The controls

Four controls, and each answers a different question

People imagine one big permission setting. There are four, they are not alternatives, and every one of them can only narrow what happens.

The card

Four answers, and what each one writes down

Two answers are about this moment. Two are about every moment after it. That is the only difference — and it is why “always” must be written on the server, not whispered to a client.

The design decision

Why the card never expires — and what that costs

The obvious design puts the question on the machine being asked about. It fails the moment you walk away from that machine, and it fails silently.

The trade-off, stated plainly. Moving consent to the server removes the machine’s per-command veto. A compromised server could drive an enrolled machine whose switch is on. That is exactly why the switch exists, why it has no “ask”, and why the daemon enforces it with no server involvement. One brake that the building genuinely cannot reach.

The judge

Auto-review: two tiers, per-field, and a model reading the actual command

Grants answer “is this tool allowed at all?”. Auto-review answers the harder question: “is this particular command, with these arguments, something we said yes to?” A model reads the call against instructions written in plain language.

The invariant

At most one card per tool call

Two gates can both want to ask. If both asked, a person would answer the same question twice and learn to click through. So the first one to raise a card wins, and the rest stand down.

The fourth control

Spend is a brake, not a card

Money gets its own control because it fails differently: nobody wants to be asked to approve every model call, and nobody wants to find out afterwards. So it is a limit, checked before the call, and crossing it is a refusal — not a question.

Why points and not currency. A subscription seat truthfully costs nothing per call, so a currency budget would let seat traffic run unlimited while API traffic is capped. Points charge from what the call would have cost at list price, so a seat and a key count the same and the limit means one thing.

The invariants

What consent never does

  • Expire. There is no timeout, because there is nothing that has to guess.
  • Live in a client. A rule enforced in one window is enforced for one window.
  • Get checked once at sign-in. Policy is asked on every action, every time.
  • Combine by union. Layers intersect; the narrowest answer wins.
  • Widen on a mistake. A broken deny rule matches; a broken allow rule does not.
  • Kill the run. A refusal is a result the model reads and reasons about.
  • Let a window flip the machine’s switch. That brake is the person’s alone.
  • Ask twice for one call.

One sentence

One question, asked once, in a place every device can reach — and it waits as long as you need it to.
