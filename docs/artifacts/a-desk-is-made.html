A Desk Is Made

A coworker needs a computer to type on. Where does it come from, what does it remember when it sleeps, and what exactly is lost when it dies? This is the floor that replaces renting one from somebody else.

The life

Six things can happen to a desk

Only six. Every button, every timer, every sweep in the building maps onto one of them — and the difference between the two that look alike is the whole point of the picture.

Create

What “make me a desk” actually does

Six things, in this order, and the order matters: the secret must exist before the container that needs it, and the ports must be private before anything is listening on them.

Ready

“Running” is not “ready”, and the difference has bitten everyone

A container reports itself started the instant the process exists. At that moment nothing inside it works. If the building trusts “started”, the first tool call of every session fails and it looks like a bug in the tool.

Sleep and death

What survives a nap, and what a funeral takes with it

Everything expensive to rebuild lives on the two volumes. Everything cheap lives in the container. That split is the whole hibernation design — there is no snapshot, no freeze, no clever state capture.

ThingLives inSurvives stop?Survives destroy?
Files the coworker wroteThe workspace volumeYesNo
Website logins (cookies)The browser profile volumeYesNo — and the person must log in again
Installed packagesThe container’s own diskNo — reinstalled or rebaked into the imageNo

Which coworker this desk belongs toThe building’s rowYesNo
The bearer tokenThe building’s rowYesNo

The one that surprises people. Packages installed during a run do not survive a stop. If a coworker keeps installing the same tool every morning, that is a message about the image, not a bug in hibernation — put the tool in the image and every desk has it at birth.

Where

Two places a desk can run, chosen per organisation

The wire to a desk is identical either way — the same three ports, the same bearer token, the same six endpoints. Only the thing being asked to start a container changes.

Whose

One desk each, or one desk shared

A desk is assigned to a scope, not to a coworker directly. That one indirection is what makes both models possible without a second code path.

The order

Standing it up, provable at every step

  1. Run the image by handNo building involved. Ask it for health, run a command, open the viewer. If this does not work, nothing built on top of it can.
  2. Make one desk from the building, and stop thereCreate, wait for ready, print the address and token, and do nothing else. A desk you can see but not yet use is a real milestone.
  3. Route the three tools you already haveRun a command, read a file, write a file. No new tool definitions — if these work, the wire is right.
  4. Stop it and wake itWrite a file, stop the desk, resume it, read the file back. That single test proves the volumes are mounted where you think.
  5. Turn on the screenHand the viewer URL to the window. A human watching a desk work is the moment the whole thing stops being abstract.
  6. Add eyes and handsScreenshot, click, type. Now it is a computer, not a shell with extra steps.
  7. Destroy one on purposeConfirm the volumes are gone and the row is gone. An untested destroy path is how a bill grows in the dark.

The invariants

What a desk never does

  • Call a model. It has no key and no route to one.
  • Know which coworker is using it. It takes commands; the building keeps the meaning.
  • Reach outside its jail. Paths resolve under one root, after symlinks.
  • Expose its browser debug port or its raw screen port. Ever, to anyone.
  • Die because the browser was closed. Only the services that matter are watched.
  • Keep a secret the building did not give it for this run.
  • Be reachable without the token — except health, which orchestrators must probe.
  • Outlive its volumes on destroy. Gone means gone.

One sentence

A desk is a container plus two volumes plus a secret — and the only hard part is waiting until it is genuinely ready.
