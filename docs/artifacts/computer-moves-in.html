The Computer Moves In

You have the app and you have the server. The third thing — the computer the coworker actually types on — is still rented from someone else. Here is what it is, what it is made of, and how to bring it home.

The shape

Four layers, not three

The old drawing had three floors: client, server, computer. That drawing is missing a door. Model calls do not belong to any of those three — they leave the building through open-ai-gateway, which is its own layer.

The rule of thumb. Client asks. Server decides. Box does. Gateway thinks. Anything that breaks that sentence is in the wrong layer.

The parts

What each layer is made of

“Client, server, computer” is three words for about twenty parts. These are the parts, with the name you should use for each one.

L1 Client — the window

  • Chat & transcriptRenders the turn as it streams. Owns nothing; if you close it, the work carries on.
  • Permission cardApprove · deny · cancel · expire. All four outcomes must be reported to the server. A card that times out is a “no”, never a silent “yes”.
  • Secret requestMasked box for an API key. Goes to the server, then into the box environment for one run — never into the transcript.
  • Screen viewerAn iframe onto the box’s desktop over noVNC. This is how a human watches, and how a human takes over to type a password.
  • Local exec daemonThe only part that touches your Mac. Needs the app open and a permission card approved. Mac asleep = this path is gone; the box keeps working.

L2 Server — the building

  • Auth & account sessionWho is asking. The identity every other decision hangs off.
  • TranscriptsThe durable record of the conversation. The client reads it; it does not own it.
  • Agent recordsEach coworker, and which computer it is bound to.
  • Tool routerTakes the model’s tool_calls and picks a destination: the box, the Mac, or an MCP connector. This is the piece people forget, and without it the model suggests tools and nothing happens.
  • Box lifecycle (EnsureBox)Create · wait ready · use · stop · hibernate · destroy. Mints BOX_TOKEN, mounts the volumes, publishes the ports.
  • Guardrails / auto-reviewDecides whether a tool call runs, needs a human, or is refused — before it reaches the box.
  • Connector vaultOAuth tokens for MCP servers. Prefer a connector over driving a website whenever a real API exists.

L3 Box — the desk

  • box-exec:1337Runs commands, reads and writes files, and performs computer use. POST /v1/exec, GET|PUT /v1/files, POST /v1/cua/*.
  • box-host:1340Says who this box is and whether it is up: /v1/health, /v1/ready, /v1/info. The orchestrator polls it. It runs no models.
  • Xvfb + openboxdisplay :1 · 1280×800A screen that no monitor is attached to. Everything the agent “sees” is this framebuffer.
  • x11vnc + noVNC:6080 published · 5900 localTurns that screen into a web page so a human can watch or take over.
  • ChromiumCDP :9222, localhost onlyThe agent’s browser, with a profile on a volume so logins survive a restart. Closing it must not kill the box.
  • Workspace jail/workspaceEvery path resolves under this root, after symlinks. /workspace-evil is not inside /workspace.

L4 Gateway — the front door

  • open-ai-gateway:29080 inferenceOne door for every model call. Anthropic- and OpenAI-shaped. Routes the cheap majority cheaply and escalates when the work needs it.
  • Admin & dashboard:29081What you spent, against what frontier-for-everything would have cost.
  • What it is notIt does not execute tools. It does not manage containers. It has never heard of a box.

The words

Three different things are called “gateway”

This is the single most expensive confusion in the stack, because two of them are reachable over HTTP and both answer.

Say thisNot thisBecause
Box / computer (L3)“the sandbox”, “the VM”It is a container with a screen, a browser and a jail — the sandbox is one property of it, not its name.
box-exec :1337“exec-daemon”exec-daemon is the vendor’s binary. Yours is your own wire; do not borrow the name.
box-host :1340“sand-host”, “the gateway”Same reason, plus it collides with L4.
CUA = Computer Use“computer user agent”Screenshot, then click or type. Against the box screen.
EnsureBox“box API”It is the lifecycle owner on L2, not a proxy in front of the box.
Local exec“box exec on the Mac”Different path, different permissions, different machine. They are never substitutes.
Connector (MCP)“plugin”A plugin is a capability bundle you install; a connector is an MCP server with structured tools and an OAuth token in the vault.

The process

One turn, all the way through

A single message from you crosses every layer, twice. The numbers are the order.

  1. You send a messageFrom the desktop app, or a phone, or the web console. The client just posts it.
  2. The server checks who you are and writes it downAuth, then the message is appended to the durable transcript. Now it survives you closing the app.
  3. The server asks the model, through the gatewayPrompt plus the list of tools this coworker is allowed to use. The gateway picks the model and bills it.
  4. The model answers with tool calls“Run npm test.” “Read this file.” “Take a screenshot.” It cannot run any of them itself.
  5. The tool router decides where each one goesBox, your Mac, or an MCP connector — and asks the guardrail first. A risky one raises a permission card and waits for your answer.
  6. The box does the workPOST /v1/exec with the bearer token. Or a file. Or a click on the box’s own screen. Results come back as data.
  7. The server stitches the results back into the turnAnd writes the activity frames the client is watching.
  8. Back to the model to continueLoop from step 4 until the model has a final answer.
  9. The reply streams to the clientWhich was only ever a window onto step 2’s transcript.

The move

Renting a desk vs. owning one

Right now the computer layer is box.ascii.dev — somebody else’s API, somebody else’s lifecycle, somebody else’s idea of what a box is. It works, and it costs you the two things a control plane exists to own: when a box exists and what its wire looks like.

Who owns itRented (box.ascii.dev)Owned (hexuria/box)
When a box existsTheir lifecycle APIYour EnsureBox — create, stop, hibernate, destroy
The auth secretTheir account key, one for everyoneBOX_TOKEN per box, minted on create, stored beside the box row
The wireWhatever they shipPOST /v1/exec, GET|PUT /v1/files, POST /v1/cua/*
The imageFixedYour Dockerfile — add a language runtime and it is there next boot
Where files liveTheir diskA volume you mount at /workspace
Cookies / loginsTheir diskA volume at /home/box/chrome-profile
Network exposurePublic by constructionPrivate fabric; 5900 and 9222 never published
Cost per idle boxTheir pricingdocker stop, keep the volumes

What you are not giving up. Nothing about the box wire is exotic. It is six HTTP endpoints and a bearer token. The reason to bring it home is not features — it is that “when does a computer exist, and who may touch it” is a control-plane question, and it is currently being answered by a third party.

The screen

Computer Use is on the box, not on your Mac

When the coworker “uses a computer”, it takes a screenshot of a screen that no monitor is attached to, and clicks on that. Your own machine is a completely separate path with a completely separate permission model.

The secrets

Four kinds of secret, four different homes

Getting this wrong is how a password ends up in a transcript. Each class has exactly one place it is allowed to rest.

The good news

You already built the hole. You just need a new plug.

The server does not call box.ascii.dev from all over the place. Every call goes through one async trait — Computer — with the vendor client hidden behind it. There are already two things plugged into that hole. Bringing the box home means writing a third.

The quiet coincidence. The desktop client already contains a full noVNC viewer aimed at host:1337 and a noVNC port — the shape http://{host}:{port}/vnc.html. It has never worked against your server because the server hands back an empty URL. grok-box publishes exactly those ports. Fill in one field and existing client code lights up.

The order

What to build, in the order that keeps working

Every step ends with something you can prove with curl before the next one starts. Nothing here breaks the rented path — it stays plugged into the same trait until you choose to unplug it.

  1. Run the box on its own, with no OpenGrok anywheredocker compose up --build in hexuria/box, then curl :1340/v1/ready, POST :1337/v1/exec, and open :6080/vnc.html. If this does not work, nothing downstream can. It has a smoke script for exactly this.
  2. Write the third Computer implA new module next to ascii/ and docker.rs. create = docker run the image with a freshly generated BOX_TOKEN, volumes at /workspace and the Chrome profile, ports 1337/1340/6080 published on loopback. wake = start, then poll /v1/ready until 200. run → POST /v1/exec. read_file/write_file → GET/PUT /v1/files. screen_url → the published viewer URL. stop/destroy → stop the container, keep or drop the volumes.
  3. Let an org choose itThe provisioning code already decides which computer kind a scope gets, and the database column already stores the kind per scope. Add the new variant; existing rows keep pointing at the rented boxes.
  4. Prove it with the tools you already haveshell, read_file and write_file should work against the new box with no change to the tool router, because they only ever call the trait. If they don’t, the impl is wrong — not the router.
  5. Give the trait eyes and handsAdd screenshot, click, type_text, key, scroll to Computer, each defaulting to “unsupported” so the other two impls keep compiling untouched. Implement them on the new impl against POST /v1/cua/*. Coordinates are 1280×800, origin top-left.
  6. Expose Computer Use as real toolsAdd the specs to the tool list and dispatch them beside shell. Keep the existing rule absolutely: the box id comes from the turn’s context, never from the model’s arguments. A model that can name the box it runs on can name someone else’s.
  7. Turn the screen back onReturn a real viewer URL where the server currently returns an empty string. The client’s existing noVNC machinery is built for this exact URL shape and is only dark because the field is blank.
  8. Pick one exec daemonThe desktop repo ships a TypeScript exec daemon meant to run inside a box, on port 1337. grok-box ships a Rust one, on port 1337. Two implementations of one wire is one too many — keep the Rust one in the image and retire the other, or the reverse, but write down which.
  9. Retire the rented path when you want to, not beforeBoth impls can be live at once, chosen per org. That is the whole point of having had the seam.

One thing to fix while you are in there. The server sends model calls to the gateway as POST /v1/chat/completions, but the gateway’s own canonical shape is Anthropic Messages — every other dialect is converted to it and back. You are paying for a round trip through a translator on every single turn. Moving that call to /v1/messages removes two conversions per request and nothing else.

One sentence

The client asks, the server decides, the box does the work, and the gateway is only ever asked what to say next.
