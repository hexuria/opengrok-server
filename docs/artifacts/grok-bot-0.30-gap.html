The 0.30 Gap

Official Grok Bot shipped 0.30.0. Here is what actually changed, where OpenGrok stands against it, and the short list worth doing.

What 0.30 actually is

Mostly a localization release with one significant new agent capability. Method: both asars extracted and diffed on RPC tables, IPC literals, feature gates, data-* attributes and native payloads — plus the English message catalog only, because 0.30 added ~2,700 translated strings that drown a naive string diff.

The headline

macOS Messages (iMessage), read and send

Local-tool actions gained read-messages and send-imessage. Reading snapshots a temp copy of chat.db via SQLite; sending goes through their existing signed computer-use-mac helper. Needs macOS Full Disk Access plus Automation, adds 12 daemon frame kinds, and relays cloud→desktop through new GrokBotUserComputerMessages protos. It reuses the local-tool permission model rather than inventing one.

Three things they removed

Org Chart / Bot network (the whole agent-graph UI), Threads tray (“Reply in thread”), and the accent colour preference. Threads matters to us: it was on our backlog from the 0.29 analysis — it is now something they don’t have either, so it comes off the list.

Three things that look new but aren’t

Voice calls ship in both 0.29 and 0.30, gated sand_voice_call and off by default in both. 0.30 only reworked the tray and refactored the code; the new voice-call package contributes no code to any shipped bundle — it’s a test harness.

tree-sitter and cursor-proclist were already in 0.29. tree-sitter parses bash for command-risk analysis (redirects, substitutions); proclist backs process telemetry with names SHA-256 hashed unless they’re the app’s own helpers.

Still no per-message delete or edit — zero occurrences anywhere in 0.30. The only per-message mutation is a reaction. That independently confirms the device-local tombstone approach we shipped was the only available path.

Out of scope by design

Marketplace · enterprise usage · virtual card · shared team agents · template export policy · onboarding catalog — all Cursor-service-bound, which is precisely what we bypass.

Where we are ahead of 0.30

  • Per-message delete — they have none at any layer; we ship it (true delete where our host owns the store, device-local tombstones elsewhere).
  • Multi-select + Collections — share/bookmark sets, dedicated window, self-contained HTML export, JSON import/export.
  • Shareable message deep links with engine-teleport jump-loading.
  • Media inspector + layout lint with a persistent findings report.
  • Transcript stability — exact estimator heights, width-keyed text heights, right-sized variants. Measured 0 layout shifts; 0.30 still estimates rows from per-kind constants.

Verdict

0.30 does not move the goalposts. Two candidates worth queueing, in order: the macOS Messages tool, then the two small renderer patches carried since 0.29 (emoji shortcode completion, a11y announcers). Everything else is service-bound, gated off upstream, or has been deleted by them.
