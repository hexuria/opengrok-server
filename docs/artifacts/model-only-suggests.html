OpenGrok · picture book · hard topic 1

The Model Only Suggests

A model cannot run a command, read a file or click a button. It can only say “I would like to.” This is everything that happens between that sentence and something actually happening — drawn against the building, floor by floor.

The path

One tool call, eight stations, five floors

The model answers with a tool call. From that moment the model is out of the room. Every station below is the building’s, and each one can say no.

  1. The model suggestsInference returns a tool call: a name and arguments. The harness receives it as part of the turn. Nothing has happened yet.
  2. The registry checks it exists and is grantedBuilt-in, plugin skill, or connector tool — and does this coworker have it? An unknown or ungranted tool is answered with a refusal result, not an error.
  3. The router picks a destinationDesk, the person’s machine, or a connector. It reads the coworker’s harness kind and the tool’s nature. This is a decision on paper; nothing is called yet.
  4. Policy answers one question: may it?Grants, the remote-control gate (Mac only), and auto-review — combined by intersection. Three outcomes: allow, ask (a card; the run suspends), deny (a refusal result).
  5. The executor overwrites identity and makes sure the desk is awakeEvery identity argument is replaced with the session’s. If the destination is a desk, Computers wakes it and hands over a token. Then, and only then, the call goes out.
  6. The destination does the work and hands back datastdout, stderr, exit code, a file, a screenshot. Bounded, with a timeout. Never a live handle into the building.
  7. The record is writtenThe result becomes a transcript entry and an activity frame. A refusal is written the same way — the model will read it as a result.
  8. The harness continuesResults go back to Inference for the next step. Loop until the model has nothing more to suggest.

The exits

Three doors out of the router, one executor behind all of them

The executor is the same code for all three. What changes is the transport, the secret that opens the door, and who has to say yes first.

Prefer the right-hand door. If a real API exists, a connector beats driving the website on the desk. The desk’s browser is for sites that have no door of their own.

Station 4

“May it?” is three questions, and the answers intersect

No single yes is enough. Each layer can only narrow; a typo in a rule can only ever remove access, never add it.

Station 5

The model never gets a say in whose data it touches

Validation asks “is this argument allowed?” and can be fooled. Overwriting does not ask; it replaces. Before any tool runs, every identity argument is thrown away and the session’s own identity is written in its place.

When the answer is “ask”

A card is not a failure. The run goes to sleep.

The executor raises a card and the run suspends at that station. It is a state in the harness graph, saved like any other. The desk stays assigned. The person answers from whatever device they have in hand, and the run wakes at the same step.

Inside station 5

“Make sure the desk is awake” is one call to Computers

The executor does not know how a desk is made. It asks the Computers floor for a ready desk for this run and gets back an address and a token. Everything else is that floor’s business.

Same path, many times

Computer Use is just tool calls, quickly

There is no special mode. A screenshot is a tool call. A click is a tool call. Each one walks all eight stations. What makes it feel different is that the model asks for a hundred of them in a row.

The invariants

What the model never gets to do

  • Name the desk it runs on. The run’s context does.
  • Name whose records a tool touches. Bind overwrites it.
  • See a bearer token, an OAuth token, or a provider key.
  • Reach a desk, a machine, or a connector directly. Only the executor calls out.
  • Turn a refusal into a crash. “No” always comes back as a result.
  • Skip a station. Every tool, every time, all eight.

One sentence

The model writes a wish; the registry reads it, the router addresses it, policy signs it, the executor seals it, the desk opens it — and the record keeps the receipt.
