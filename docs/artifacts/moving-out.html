Moving Out

A modular monolith is only modular if a floor can leave. This is what leaving actually involves, what it costs, how to tell whether a seam was real — and the honest answer to when you should bother.

The test

Three things change. Nothing else may.

A floor moving out is not a rewrite. It is three specific substitutions, and if a fourth is needed, the seam was never a seam.

The proof

What a fake seam looks like when you pull on it

You do not discover a fake seam by reading code. You discover it the moment something has to become a network call, because these four things stop working and each one is a redesign.

A worked example

Moving Inference out, step by step

The best candidate, and a useful rehearsal: it already has a public face, it is the floor most likely to need its own machines, and its interface is the narrowest in the building.

  1. Confirm the seam is realDoes anything join its metering tables to another floor’s? (Policy reads spend — check it does so through the interface or an event, not a join.) Does anything call past its interface? Fix those first. This is the actual work; the rest is mechanical.
  2. Give the interface a remote implementationSame shape, over a wire. Now two implementations exist: in-process and remote. Nothing else in the building knows there is a choice.
  3. Run it out of process, but talk to it in-processStart the floor as its own service and keep every caller on the in-process path. If it boots and passes its own tests alone, its dependencies are honest.
  4. Switch one callerPoint the least important caller at the remote implementation. Watch latency and errors. You have now proven the wire without betting the product on it.
  5. Switch the rest, keep the switchMove everyone. Leave the in-process implementation in place — it is the fastest possible local development setup, and the fallback if the wire misbehaves.
  6. Move its tables lastOnly after the wire is boring. Its tables were already private, so this is a data move rather than a schema change.
  7. Drain events through a brokerThe outbox already holds the rows. Point its drain at a real broker instead of the in-process bus. Subscribers do not change.

Step 3 is the honest test. A floor that cannot boot alone has a dependency it never declared — usually a shared helper that quietly reads another floor’s tables. Better to find that in a terminal than during an incident.

The honest part

When to actually do this — and when not to

Extraction is a cost you pay for a benefit you may not need. The design guarantees you can; it does not suggest you should.

The scoreboard

What each floor would cost to move today

FloorDifficultyThe reason
InferenceEasiestNarrow interface, already has a public face, no other floor reads its tables.
ComputersEasyAlready talks over a network to desks. Its interface is “ensure me a desk”.
Connectors & SecretsEasyAlready reaches outside. Holds tokens, so its own blast radius is an argument for moving it.
AutonomyModerateNeeds the event stream and the claim mechanism. Both travel, but the claim wants care.
ToolsModerateChatty with Policy on every call. Extraction adds a round trip to the hottest path in the building.
ConversationHarderEverything watches it. High traffic, and the transcript is the event log.
AgentsHardestTouches almost every other floor by design. If this needs to move, the problem is probably elsewhere.
IdentityDo notEvery request starts here. Moving it puts a network hop in front of literally everything.

Read the table as a design review, not a plan. The floors that would be hard to extract are hard because they are genuinely central — not because they are badly built. A floor that is easy to move and also central would be the real warning sign.

The invariants

The rules that keep the option open

  • Never write a query that names two floors’ tables.
  • Never share a transaction across two floors. Decide who owns the write.
  • Never call past an interface, however convenient the function looks.
  • Never assume a call cannot fail. Design as if it were already remote.
  • Never let the kernel learn a floor’s name.
  • Never put a rule in a door.
  • Never let a floor poll another instead of listening for its events.
  • Never extract for tidiness. Extract for hardware, scale, blast radius or ownership.

One sentence

Build every floor as though it will move out tomorrow, and then enjoy never having to move one.
